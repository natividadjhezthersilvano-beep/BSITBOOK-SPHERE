Overview

Web forms are an essential part of modern websites because they allow users to enter information, make selections, and send data to a web server. They provide a way for websites to communicate with users and collect information needed to perform different operations.

Forms are commonly used for account registration, login pages, contact pages, online applications, surveys, feedback systems, search engines, and online purchases.

HTML provides different elements for building forms. The main element is the form tag, which acts as a container for input fields, buttons, selection menus, and other form controls.

After users complete the required fields, they can submit the form. The submitted information is transmitted to a server-side program or API, where it can be validated, processed, stored, or used to perform an action.

Form validation is also important because it helps ensure that the information entered by users follows the expected format and requirements.

Understanding Web Forms

A web form is a document or interface that provides fields where users can enter text, numbers, personal information, or choose from a list of available options.

The information entered into a form is called user input. The form collects this information and sends it to a server for processing when the user submits it.

How Web Forms Work

A user opens a webpage containing a form and enters the requested information. The user may type a name, email address, phone number, or password, or select an option from a dropdown menu.

Before submission, the browser may check whether the information satisfies the form's validation requirements. If the information is valid, the browser sends the form data to the specified destination.

The server receives the information and processes it. Depending on the application, the server may save the information in a database, create an account, send an email, or return a response to the user.

Common Examples of Web Forms

Registration Form: Collects a user's name, email address, username, and password when creating an account.

Login Form: Collects the username or email address and password needed to access an account.

Contact Form: Allows visitors to send questions, concerns, suggestions, or messages to a website owner.

Search Form: Accepts keywords or phrases that users want to search for.

Feedback Form: Collects comments, ratings, complaints, and suggestions from users.

Order Form: Collects product selections, quantities, delivery information, and customer details.

Form Controls

Form controls are the elements that allow users to enter, select, edit, or submit information.

Examples include textboxes, checkboxes, radio buttons, dropdown menus, buttons, and text areas.

The Form Tag

The <form> element is the main container used to create an HTML web form. It groups different form controls and defines how their data will be submitted.

Form controls such as text fields, checkboxes, radio buttons, dropdown menus, and submit buttons are placed inside the form element.

Basic Form Structure

<form action="process.php" method="post">

    <label for="name">Full Name:</label>
    <input type="text" id="name" name="fullname">

    <button type="submit">Submit</button>

</form>

In this example, the form contains a text field for the user's full name and a submit button. When the button is clicked, the browser sends the form data according to the specified method and destination.

Important Parts of the Form

Opening Form Tag: Starts the form container and defines its submission settings.

Form Controls: Provide the fields where users enter or select information.

Submit Button: Allows the user to submit the completed form.

Closing Form Tag: Marks the end of the form container.

GET and POST Methods

The method attribute specifies which HTTP method the browser uses when submitting form data. The two commonly used methods are GET and POST.

GET Method

The GET method sends form data as part of the URL. The field names and values are included as URL parameters in the request.

GET is commonly used for search forms, filtering, and other requests that retrieve information. 

<form action="search.php" method="get">

    <label for="keyword">Search:</label>

    <input type="text" id="keyword" name="q">

    <button type="submit">Search</button>

</form>

A submitted search might produce a URL similar to: 

search.php?q=computer

Because the values appear in the URL, GET should not be used for passwords or other sensitive information. URLs may be stored in browser history, server logs, and shared links.

POST Method

The POST method sends form data in the body of the HTTP request instead of placing the values directly in the URL.

POST is commonly used for registration, login, feedback, file uploads, and other operations that submit information for processing or storage. 

<form action="register.php" method="post">

    <label for="email">Email:</label>

    <input type="email" id="email" name="email">

    <button type="submit">Register</button>

</form>

POST keeps submitted values out of the URL, but it does not automatically encrypt them. HTTPS is required to protect information while it travels between the browser and server.

GET vs. POST

GET: Sends form data through URL parameters and is appropriate for retrieving information.

POST: Sends form data in the request body and is commonly used when submitting information for processing.

GET: Submitted values may appear in browser history and can be bookmarked or shared.

POST: Submitted values are not normally displayed in the URL.

Security: Neither method alone provides encryption. Use HTTPS to protect transmitted information.

Form Attributes

Form attributes define how the form behaves, where information is sent, and how the browser handles submitted data.

action

The action attribute specifies the URL of the server-side script or API endpoint that receives and processes the submitted form data. 

<form action="process.php" method="post">

method

The method attribute specifies how the browser submits form information. Common values are get and post. 

<form method="post">

accept-charset

The accept-charset attribute specifies the character encoding used when submitting the form. UTF-8 is commonly used for modern websites. 

<form accept-charset="UTF-8">

autocomplete

The autocomplete attribute controls whether the browser can automatically fill in previously entered information. 

<form autocomplete="on">

It can also be set to off when automatic completion should not be used for the form.

enctype

The enctype attribute specifies how form data is encoded when the POST method is used.

application/x-www-form-urlencoded: The default encoding for standard form submissions.

multipart/form-data: Used when a form includes file uploads. 

<form method="post"
      enctype="multipart/form-data">

    <input type="file" name="document">

</form>

name

The name attribute identifies the form. It can be useful when accessing the form through JavaScript. 

<form name="registrationForm">

novalidate

The novalidate attribute tells the browser not to perform its normal built-in form validation before submission. 

<form novalidate>

target

The target attribute specifies where the response from the server should be displayed.

For example, the value _blank opens the response in a new browsing context. 

<form action="process.php"
      method="post"
      target="_blank">

These attributes help developers configure the behavior and submission process of HTML forms.

Form Controls and Labels

Form controls are HTML elements that allow users to provide information, choose options, or perform actions within a form.

The Label Element

The <label> element provides a visible description for a form control. It tells users what information they should enter or select.

Labels also improve accessibility. When properly connected to a form control, clicking the label can activate or focus the associated field.

There are two common ways to associate a label with a form control.

Wrapping the Control

<label>
    Subscribe:
    <input type="radio" name="subscribe">
</label>

Using the for Attribute

<label for="subscribe">Subscribe:</label>

<input type="radio"
       name="subscribe"
       id="subscribe">

The value of the label's for attribute must match the id of the form control.

The name Attribute

The name attribute identifies a form control when its value is submitted to the server. Without an appropriate name, a control's value is generally not included in the submitted form data. 

<input type="text" name="fullname">

The value Attribute

The value attribute specifies the value associated with a form control. It can provide a default text value or define the value submitted when an option is selected. 

<input type="text"
       name="username"
       value="Student">

The placeholder Attribute

The placeholder attribute displays temporary instructional text inside an input field. It disappears when the user starts typing. 

<input type="tel"
       name="phone"
       placeholder="09XX-XXX-XXXX">

A placeholder is a helpful hint, but it should not replace a proper label because the hint disappears during data entry.

HTML Input Types

The <input> element is one of the most commonly used form controls in HTML. Its type attribute determines what kind of input field the browser displays.

Different input types are designed for different kinds of information. Choosing the correct type improves usability and provides basic browser validation.

Text Input

The text type creates a general textbox that accepts ordinary text, such as names, usernames, and other short information. 

<input type="text" name="fullname">

Password Input

The password type creates a field that hides the characters entered by the user, usually displaying dots or bullets instead. 

<input type="password" name="password">

Email Input

The email type creates a field for email addresses. The browser checks whether the entered value follows a basic email format. It does not confirm that the email address actually exists. 

<input type="email" name="email">

Telephone Input

The tel type creates a field intended for phone numbers. It can provide a suitable mobile keyboard, but it does not automatically enforce one universal telephone number format. 

<input type="tel"
       name="phone"
       placeholder="09XX-XXX-XXXX">

Number Input

The number type creates a field for numeric values. Browsers commonly display controls that allow users to increase or decrease the value. 

<input type="number"
       name="age"
       min="1"
       max="100">

Checkbox Input

The checkbox type creates a small square control that users can check or uncheck. Multiple checkboxes can be selected at the same time. 

<label>
    <input type="checkbox" name="interests" value="coding">
    Coding
</label>

<label>
    <input type="checkbox" name="interests" value="design">
    Web Design
</label>

Radio Input

The radio type creates a circular selection control. Radio buttons with the same name are grouped together, allowing users to select only one option from that group. 

<label>
    <input type="radio" name="year" value="first">
    First Year
</label>

<label>
    <input type="radio" name="year" value="second">
    Second Year
</label>

Submit Input

The submit type creates a button that submits the form when clicked. 

<input type="submit" value="Submit">

Reset Input

The reset type creates a button that restores form controls to their initial values. 

<input type="reset" value="Clear">

Button Input

The button type creates a general clickable button. It does not submit the form by default and is commonly connected to JavaScript. 

<input type="button" value="Click Me">

File Input

The file type creates a control that allows users to browse and select files from their devices. 

<input type="file" name="document">

Hidden Input

The hidden type stores a value in the form without displaying a visible input control to the user. 

<input type="hidden"
       name="formType"
       value="feedback">

Hidden fields are not secure storage. Users can inspect and modify their values, so the server must never trust them without verification.

Color Input

The color type provides a color picker that allows users to select a color value. 

<input type="color" name="favoriteColor">

Date Input

The date type provides a date picker for selecting a calendar date. 

<input type="date" name="birthdate">

Datetime-local Input

The datetime-local type allows users to select both a date and a time without specifying a time zone. 

<input type="datetime-local" name="appointment">

Month Input

The month type allows users to select a specific month and year. 

<input type="month" name="enrollmentMonth">

Week Input

The week type allows users to select a particular week of a year. 

<input type="week" name="scheduleWeek">

Time Input

The time type provides a control for selecting a particular time of day. 

<input type="time" name="classTime">

Range Input

The range type creates a slider that allows users to select a numeric value within a specified range. 

<input type="range"
       name="rating"
       min="1"
       max="10">

Search Input

The search type creates a textbox intended for entering search terms. 

<input type="search" name="keyword">

URL Input

The url type creates a field for website addresses. The browser checks whether the entered value follows a basic URL format. 

<input type="url" name="website">

Image Input

The image type creates an image-based submit control. It can use the src attribute to specify the image displayed on the button. 

<input type="image"
       src="submit.png"
       alt="Submit Form">

The type attribute should be selected based on the information being collected. Using the correct input type makes forms easier to use and can provide built-in browser validation.

Other Form Controls

In addition to the input element, HTML provides several other elements for building more organized and flexible forms.

Button Element

The <button> element creates a customizable button. It can be used to submit a form, reset form controls, or perform an action through JavaScript. 

<button type="submit">Submit Form</button>

<button type="reset">Clear Form</button>

<button type="button">Open Details</button>

A button inside a form may act as a submit button by default. Specify its type explicitly to avoid unexpected form submissions.

Select Element

The <select> element creates a dropdown menu or listbox that allows users to select one or more options. 

<label for="course">Choose a Course:</label>

<select id="course" name="course">
    <option value="bsit">BSIT</option>
    <option value="bsba">BSBA</option>
    <option value="beed">BEED</option>
</select>

A dropdown menu conserves screen space because the available options are displayed when the user opens it.

The size attribute can display multiple options as a listbox. The multiple attribute allows users to select more than one option. 

<select name="subjects" size="4" multiple>
    <option value="html">HTML</option>
    <option value="css">CSS</option>
    <option value="javascript">JavaScript</option>
    <option value="database">Database</option>
</select>

Option Element

The <option> element defines an individual choice inside a select menu or datalist. Its value attribute identifies the selected value submitted with the form. 

<option value="bsit">
    Bachelor of Science in Information Technology
</option>

Optgroup Element

The <optgroup> element groups related options inside a dropdown menu. The label attribute provides a visible name for the group. 

<select name="reason">

    <optgroup label="Feedback">
        <option value="complaint">Complaint</option>
        <option value="compliment">Compliment</option>
        <option value="comment">Comment</option>
    </optgroup>

    <optgroup label="Request">
        <option value="catering">Catering</option>
        <option value="suggestion">Suggestion</option>
    </optgroup>

</select>

Textarea Element

The <textarea> element creates a multiline text field. It is useful when users need to enter longer messages, comments, feedback, or descriptions. 

<label for="comments">Comments:</label>

<textarea id="comments"
          name="comments"
          rows="5"
          cols="40"
          placeholder="Write your message here..."></textarea>

The rows attribute controls the initial visible height, while cols controls the initial visible width. Users can usually resize a textarea unless CSS prevents it.

Fieldset Element

The <fieldset> element groups related form controls together. It creates a visible grouping around the controls. 

<fieldset>

    <legend>Personal Information</legend>

    <label for="firstName">First Name:</label>
    <input type="text" id="firstName" name="firstName">

    <label for="lastName">Last Name:</label>
    <input type="text" id="lastName" name="lastName">

</fieldset>

Legend Element

The <legend> element provides a caption or title for a fieldset. It helps users understand the purpose of the grouped controls.

Datalist Element

The <datalist> element provides a list of suggested values for an input field. Users can select one of the suggestions or type their own value. 

<label for="browser">Choose a Browser:</label>

<input list="browsers"
       id="browser"
       name="browser">

<datalist id="browsers">
    <option value="Chrome">
    <option value="Firefox">
    <option value="Edge">
    <option value="Safari">
    <option value="Opera">
</datalist>

The input element's list attribute must match the id of the datalist element.

Output Element

The <output> element displays the result of a calculation or an action performed by JavaScript. 

<form oninput="result.value =
    Number(first.value) + Number(second.value)">

    <input type="number" id="first" value="0">

    +

    <input type="number" id="second" value="0">

    =

    <output name="result">0</output>

</form>

These additional controls help developers create organized forms that support different types of user information and interactions.

Form Validation

Form validation is the process of checking whether the information entered by users meets the expected requirements before it is accepted or processed.

Validation is important because incorrect, incomplete, or improperly formatted information can cause errors in an application or database.

For example, a registration form should not accept an empty email address, an invalid age, or a missing password if those fields are required.

Why Validation Is Important

Data Accuracy: Helps ensure that information follows the expected format.

Completeness: Makes sure that required fields are not left empty.

User Experience: Helps users identify and correct mistakes before submitting a form.

Data Processing: Reduces the chance of receiving unusable or unexpected information.

Security: Helps detect suspicious or unexpected input, although validation alone does not guarantee security.

Three Methods of Form Validation

HTML forms can use three main approaches to validation: input type validation, HTML validation attributes, and JavaScript validation.

Input Type Validation

Each input type has its own built-in validation behavior. For example, an email field checks the general format of an email address, while a number field checks whether the value is numeric. 

<input type="email" name="email">

<input type="number" name="age">

HTML Validation Attributes

HTML validation attributes add requirements to form controls. They can make fields mandatory, limit the number of characters, set numeric ranges, and check input patterns. 

<input type="text"
       name="username"
       required
       minlength="4"
       maxlength="20">

JavaScript Validation

JavaScript can examine form values and apply custom validation rules that go beyond the built-in HTML requirements.

It is useful when a form requires special conditions, comparisons between fields, custom error messages, or more complex validation logic. 

const form = document.querySelector("#registration");

form.addEventListener("submit", function(event) {

    const password =
        document.querySelector("#password").value;

    const confirmPassword =
        document.querySelector("#confirmPassword").value;

    if (password !== confirmPassword) {

        event.preventDefault();

        alert("Passwords do not match.");

    }

});

Client-side validation improves the user experience, but it must not be the only validation method. The server must also validate submitted information because users can bypass browser-side checks.

Validation Attributes

HTML provides several attributes that define the requirements for values entered into form controls. These attributes allow browsers to perform basic validation without requiring additional JavaScript.

required

The required attribute makes a field mandatory. The browser prevents normal form submission if the field is empty or otherwise lacks a required selection. 

<input type="text" name="fullname" required>

min

The min attribute defines the minimum acceptable numeric or date value. 

<input type="number" name="age" min="18">

max

The max attribute defines the maximum acceptable numeric or date value. 

<input type="number" name="age" max="100">

minlength

The minlength attribute specifies the minimum number of characters required in a text field. 

<input type="text" name="username" minlength="5">

maxlength

The maxlength attribute specifies the maximum number of characters that can be entered. 

<input type="text" name="username" maxlength="20">

pattern

The pattern attribute specifies a regular expression that the input value must match. It is useful for checking specific formats. 

<input type="text"
       name="studentID"
       pattern="[0-9]{4}-[0-9]{4}"
       title="Enter the format 2026-1234">

step

The step attribute defines the valid increments for numeric or date-related inputs. 

<input type="number"
       name="quantity"
       min="0"
       max="100"
       step="5">

Multiple Validation Attributes

Several validation attributes can be combined in a single input field. 

<input type="number"
       name="frequency"
       min="0"
       max="7"
       required>

This example requires the user to enter a number between zero and seven.

Regular Expressions and Pattern Validation

A regular expression, commonly called a regex, is a sequence of characters that describes a pattern used to match or validate text.

Regular expressions are useful when a form requires a specific format, such as an identification number, postal code, phone number, or username.

Example of Pattern Validation

<input type="text"
       name="studentID"
       pattern="[0-9]{4}-[0-9]{4}"
       title="Use the format 1234-5678">

In this example, the pattern requires four digits, a hyphen, and another four digits.

Understanding Common Regex Symbols

[0-9] matches a digit from zero through nine.

[A-Z] matches an uppercase letter.

[a-z] matches a lowercase letter.

{4} means the preceding pattern must occur exactly four times.

+ means one or more occurrences.

* means zero or more occurrences.

? means zero or one occurrence.

^ represents the beginning of a string in a regular expression.

$ represents the end of a string.

\. matches a literal period.

Email Format Example

<input type="text"
       name="email"
       pattern="[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}"
       title="Enter a valid email format"
       required>

The pattern checks for a sequence of allowed characters, an @ symbol, a domain name, and a domain extension.

Regular expressions should be designed carefully. They can validate a basic format, but they cannot prove that an email address or phone number actually belongs to a real person.

Form Security and Safe Data Handling

Web forms may collect personal and sensitive information. Developers must ensure that the information is handled securely when it is transmitted, processed, and stored.

Use HTTPS

HTTPS protects information while it travels between the user's browser and the web server. It helps prevent attackers from reading or modifying data during transmission.

POST does not automatically encrypt form data. HTTPS is needed to protect the connection.

Validate Data on the Server

Browser validation can be bypassed. A user can disable JavaScript or send a request without using the normal form interface.

Therefore, the server must independently check all submitted information before accepting it.

Prevent SQL Injection

SQL injection is an attack where malicious SQL statements are inserted into input fields in an attempt to manipulate database queries.

For example, an attacker may enter unexpected SQL commands into a login or search field. If the server directly combines that input with a database query, the database may execute unintended commands.

Developers should use parameterized queries or prepared statements rather than directly joining user input into SQL statements.

Prevent Cross-Site Scripting

Cross-Site Scripting (XSS) occurs when untrusted content is treated as executable script or markup in a webpage.

Developers should safely handle user-provided content, encode output appropriately, and avoid inserting untrusted input as raw HTML.

Protect Sensitive Information

Passwords should never be stored as plain text. Applications should use appropriate secure password hashing methods on the server.

Hidden form fields should not be trusted for authorization or other security decisions because users can inspect and change their values.

Practical Activity: Creating a Contact Form

This activity demonstrates how to combine form elements, labels, input types, dropdown menus, text areas, fieldsets, and validation attributes to create a complete contact form.

Complete HTML Code

<!DOCTYPE html>
<html lang="en">

<head>

    <meta charset="UTF-8">

    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>Contact Us</title>

</head>

<body>

    <header>
        <h1>Our Story</h1>
        <p>Learn more about our organization.</p>
    </header>

    <main>

        <h2>Contact Us</h2>

        <form action="process.php"
              method="post"
              id="contactusform"
              autocomplete="on">

            <fieldset>

                <legend>Personal Information</legend>

                <label for="fname">First Name:</label>

                <input type="text"
                       id="fname"
                       name="fname"
                       placeholder="Enter first name">

                <br><br>

                <label for="lname">Last Name:</label>

                <input type="text"
                       id="lname"
                       name="lname"
                       placeholder="Enter last name"
                       required>

                <br><br>

                <label for="phone">Phone:</label>

                <input type="tel"
                       id="phone"
                       name="phone"
                       placeholder="09XX-XXX-XXXX">

                <br><br>

                <label for="email">Email:</label>

                <input type="email"
                       id="email"
                       name="email"
                       placeholder="example@email.com"
                       required>

            </fieldset>

            <br>

            <label for="reason">
                Reason for Communication:
            </label>

            <br>

            <select id="reason" name="commenttype">

                <optgroup label="Feedback">

                    <option value="comment">
                        Comment
                    </option>

                    <option value="compliment">
                        Compliment
                    </option>

                    <option value="complaint">
                        Complaint
                    </option>

                </optgroup>

                <optgroup label="Request">

                    <option value="catering">
                        Catering
                    </option>

                    <option value="suggestion">
                        Suggestion
                    </option>

                </optgroup>

            </select>

            <br><br>

            <label for="frequency">
                How many days per week do you visit?
            </label>

            <br>

            <input type="number"
                   id="frequency"
                   name="frequency"
                   min="0"
                   max="7"
                   required>

            <br><br>

            <label for="comments">Comments:</label>

            <br>

            <textarea id="comments"
                      name="comment"
                      rows="6"
                      cols="40"
                      placeholder="Write your message here..."
                      required></textarea>

            <br><br>

            <button type="submit">
                Submit
            </button>

            <button type="reset">
                Clear
            </button>

        </form>

    </main>

</body>

</html>

Explanation of the Activity

The form begins with the form element, which specifies the submission destination and POST method.

The fieldset element groups the user's personal information, while the legend provides a title for that group.

Each input field has a label that identifies the information being requested.

The text input collects first and last names. The telephone input collects a phone number, and the email input checks the general format of an email address.

The select element creates a dropdown menu with separate Feedback and Request groups using optgroup and option elements.

The number input uses min and max attributes to restrict the allowed value from zero to seven.

The textarea provides a larger area for entering comments and messages.

The required attribute makes the last name, email, frequency, and comments fields mandatory.

The submit button sends the form, while the reset button restores the fields to their initial values.

For this example to actually save or send data, the form must connect to a working server-side handler at the specified action address.

Practical Applications of Web Forms

HTML forms are used in different types of websites and information systems because they provide a standard way to collect and submit user information.

Student Registration Systems: Collect student names, contact details, addresses, academic information, and enrollment preferences.

School Feedback Systems: Allow students and visitors to submit comments, complaints, suggestions, and evaluations.

Online Shopping: Collect customer information, delivery addresses, product selections, and order quantities.

Login and Registration: Collect account credentials and information needed to create or access user accounts.

Search Engines: Allow users to enter keywords and search for information.

Appointment Systems: Collect dates, times, contact details, and appointment preferences.

Online Surveys: Collect responses through text fields, checkboxes, radio buttons, and dropdown menus.

Job Application Systems: Allow applicants to provide personal details, qualifications, and uploaded documents.

Key Takeaways

HTML forms provide an interface for collecting information from users and submitting it to a server for processing.

The form element acts as the main container for input fields, buttons, and other controls.

The action attribute identifies the destination of the form submission, while the method attribute determines how the data is transmitted.

GET sends submitted values through URL parameters, while POST sends values in the HTTP request body. HTTPS is needed to protect transmitted data.

Labels improve form usability and accessibility by identifying the purpose of each control.

Input types such as text, email, password, number, date, checkbox, radio, file, and range are designed for different types of user input.

Other HTML controls such as select, option, optgroup, textarea, fieldset, legend, datalist, output, and button help create more flexible forms.

Validation checks whether information meets the requirements before it is accepted. HTML input types, validation attributes, and JavaScript can all be used for validation.

Regular expressions can define specific text patterns, while server-side validation remains necessary for reliable data handling.

Secure form development requires HTTPS, safe database queries, appropriate output handling, and careful protection of user data.
