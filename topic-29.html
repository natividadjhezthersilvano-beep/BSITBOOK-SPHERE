Overview

Authentication, Authorization, and Web Security are important concepts in the development of websites and web applications. They help protect user accounts, personal information, application data, and restricted system resources.

Authentication is the process of verifying the identity of a user. Authorization determines what an authenticated user is allowed to access or perform. Web security involves the technologies, policies, and practices used to protect websites and applications from unauthorized access, attacks, data theft, and other security risks.

These concepts work together to ensure that users can access only the information and functions permitted by the system.

For example, when a student logs in to an online student portal, authentication verifies the student's identity. Authorization determines whether the student can view grades, update a profile, or access administrative features.

Understanding Web Security

Web security refers to the protection of websites, web applications, servers, databases, and user information from security threats and unauthorized activities.

Web applications frequently process sensitive information, including names, email addresses, passwords, financial information, personal records, and business data. Without proper security measures, attackers may exploit vulnerabilities to access, modify, steal, or destroy information.

Objectives of Web Security

Confidentiality: Ensures that sensitive information is accessible only to authorized individuals. Encryption and access controls help protect confidential information.

Integrity: Ensures that information remains accurate and is not changed without permission. Database permissions, validation, and integrity checks help protect data.

Availability: Ensures that websites and services remain accessible to legitimate users when needed. Backups, monitoring, and protection against service disruptions support availability.

The CIA Triad

The CIA Triad is a basic information security model consisting of Confidentiality, Integrity, and Availability. These three principles help organizations identify and manage security requirements.

Authentication

Authentication is the process of verifying the identity of a person, device, or system before allowing access to a protected application or resource.

It answers the question: "Who are you?"

Websites commonly use authentication when users log in using a username, email address, password, verification code, security key, or biometric method.

How Authentication Works

A user first provides identification information, such as a username or email address. The system then requests credentials, such as a password or verification code.

The application checks the submitted credentials against securely stored authentication information. If the credentials are valid, the system establishes an authenticated session or issues an authentication token.

If the credentials are incorrect, access is denied and the application may display an error message.

Authentication Process

Examples of Authentication

Logging in to a student portal using an email address and password.

Verifying an online account using a one-time password (OTP).

Unlocking a mobile application using a fingerprint or facial recognition.

Using a security key to verify access to an online account.

Authentication Factors

Authentication factors are categories of evidence used to verify a user's identity. Strong authentication can combine multiple independent factors.

Something You Know

This factor uses information that a user knows. Examples include passwords, PINs, and passphrases.

Something You Have

This factor uses a physical device or possession controlled by the user. Examples include a registered smartphone, hardware security key, or authentication token.

Something You Are

This factor uses biometric characteristics of a person. Examples include fingerprints, facial recognition, and iris recognition.

Somewhere You Are

Some systems also consider the user's location as contextual information. For example, a system may request additional verification when a login occurs from an unusual location.

Location is generally treated as a contextual or risk signal rather than a strong independent authentication factor by itself.

Authentication Methods

Different authentication methods are used depending on the security requirements, type of application, and user needs.

Password-Based Authentication

Users enter a username, email address, or other identifier together with a password. The system verifies the submitted password against a securely stored password hash.

One-Time Password (OTP)

An OTP is a temporary verification code that is generally valid for a limited time or a single authentication attempt. It may be delivered through an authenticator application, email, or SMS.

Biometric Authentication

Biometric authentication verifies a person using physical or behavioral characteristics, such as fingerprints or facial recognition.

Passkey Authentication

Passkeys use public-key cryptography to authenticate users without requiring them to remember a traditional password. The private key remains protected by the user's device or credential manager, while the corresponding public key is registered with the service.

Certificate-Based Authentication

Certificate-based authentication uses digital certificates to verify the identity of a user, device, or server. It is commonly used in enterprise environments and secure communication systems.

Single Sign-On (SSO)

Single Sign-On allows users to access multiple related applications using one authentication process. Instead of logging in separately to every application, users authenticate through a trusted identity provider.

Social Login

Social login allows users to sign in to a website using an existing account from an identity provider, such as a supported social or technology platform. It commonly uses OAuth 2.0 and OpenID Connect.

Password Security

Password security refers to the practices and technologies used to protect passwords from theft, guessing, exposure, and unauthorized use.

Passwords are commonly used to protect accounts, but weak or reused passwords can make systems vulnerable to attacks.

Characteristics of a Strong Password

A strong password should be sufficiently long, difficult to guess, and unique to the account. Passphrases made from multiple unrelated words can be easier to remember while providing substantial length.

Passwords should not contain easily guessed information such as a person's name, birthday, or common dictionary words used alone.

Password Hashing

Websites should not store users' passwords as plain text. Instead, passwords should be processed using a secure password-hashing algorithm before being stored.

Password hashing transforms a password into a fixed-length value. A properly designed password hashing algorithm makes it computationally expensive for attackers to recover passwords from stolen password databases.

Common password-hashing algorithms include Argon2id, bcrypt, and PBKDF2. These algorithms use salts and configurable computational costs to help resist password-cracking attacks.

Salt

A salt is a unique random value added to a password before hashing. It helps prevent attackers from using precomputed tables and makes identical passwords produce different stored hashes when different salts are used.

Password Reset

A password reset process allows users to regain access to an account when they forget their password. A secure reset process should verify the user's identity and use a short-lived, single-use reset token.

Password Security Practices

Do not store passwords in plain text.

Use a dedicated password-hashing algorithm.

Use unique salts for password hashes.

Require secure password reset procedures.

Protect login attempts against automated abuse.

Encourage users to use unique passwords for different accounts.

Multi-Factor Authentication (MFA)

Multi-Factor Authentication is a security method that requires users to provide two or more different authentication factors to verify their identity.

MFA adds another layer of protection because an attacker who obtains one credential may still be unable to access the account without the additional factor.

Two-Factor Authentication (2FA)

Two-Factor Authentication is a type of MFA that requires exactly two different authentication factors.

For example, a user enters a password and then confirms the login using a registered security key or an authenticator application.

Common MFA Methods

Authenticator Applications: Generate temporary verification codes or approve authentication requests.

Hardware Security Keys: Physical devices that verify authentication through cryptographic operations.

Biometric Verification: Uses a fingerprint or facial recognition as an additional verification method.

One-Time Passwords: Temporary codes used to verify a login attempt.

Benefits of MFA

Provides additional protection against stolen passwords.

Reduces the risk of unauthorized account access.

Helps protect sensitive personal and organizational information.

Can make account compromise more difficult even when a password has been exposed.

Not all MFA methods offer the same level of protection. Phishing-resistant methods, such as properly implemented passkeys and security keys, provide stronger protection against many phishing attacks than codes entered manually.

Authorization

Authorization is the process of determining what an authenticated user is permitted to access or perform within a system.

It answers the question: "What are you allowed to do?"

After a user successfully logs in, the application checks the user's permissions before allowing access to protected pages, records, files, or system functions.

Examples of Authorization

A student can view personal grades but cannot modify official academic records.

A teacher can manage class information and submit grades for assigned students.

An administrator can manage user accounts, permissions, and system settings.

Why Authorization Is Important

Authorization prevents users from accessing information or performing actions beyond their assigned permissions.

Without proper authorization, an ordinary user might gain access to administrative functions, private records, or restricted system resources.

Authentication and Authorization Process

Access Control Models

Access control is the process of managing who can access specific resources and what actions they can perform. It is commonly implemented through permissions, policies, roles, and rules.

Role-Based Access Control (RBAC)

Role-Based Access Control assigns permissions according to a user's role in an organization or application.

For example, a school portal may define Student, Teacher, Registrar, and Administrator roles. Each role receives permissions appropriate to its responsibilities.

A student may view grades, a teacher may submit grades, and an administrator may manage accounts.

Discretionary Access Control (DAC)

Discretionary Access Control allows the owner of a resource to decide which users can access it and what permissions they receive.

For example, a user who owns a shared document may grant another person permission to view or edit that document.

Mandatory Access Control (MAC)

Mandatory Access Control uses centrally defined security policies and classifications to control access. Individual users cannot freely change the security rules.

This model is commonly associated with environments that handle highly sensitive or classified information.

Attribute-Based Access Control (ABAC)

Attribute-Based Access Control evaluates attributes related to the user, resource, requested action, and environment.

For example, a system may allow a teacher to access a student's records only when the teacher is assigned to that student and is using an approved application.

Principle of Least Privilege

The principle of least privilege means that users and applications should receive only the permissions necessary to perform their assigned tasks.

For example, a student account should not receive administrator permissions if its purpose is only to view academic information.

Difference Between Authentication and Authorization

Authentication and authorization are closely related, but they perform different security functions. Authentication verifies identity, while authorization determines permissions.

Authentication

Authentication confirms who a user is. It commonly happens during the login process.

Authorization

Authorization determines what an authenticated user is allowed to access or do. It is checked whenever a protected resource or operation is requested.

Example in a School Management System

A student enters an email address and password. The system verifies the credentials. This is authentication.

After login, the system allows the student to view personal grades but prevents the student from accessing the administrator dashboard. This is authorization.

Comparison

Authentication: Verifies identity.

Authorization: Checks access permissions.

Authentication question: Who are you?

Authorization question: What are you allowed to do?

Authentication example: Entering a password and verifying an OTP.

Authorization example: Allowing an administrator to manage user accounts.

Authentication normally occurs before a user receives access to protected resources. Authorization is then evaluated for each protected action or resource request.

Sessions and Cookies

Sessions and cookies are commonly used by websites to maintain information about users as they move between pages.

Sessions

A session is a mechanism for maintaining a user's authenticated state or other temporary information across multiple requests.

After successful login, a server may create a session and associate it with a unique session identifier. The browser sends this identifier with later requests so the server can identify the session.

Cookies

Cookies are small pieces of data stored by a browser for a website. They can store session identifiers, preferences, and other information.

Authentication cookies should be configured securely to reduce the risk of theft or misuse.

Important Cookie Attributes

HttpOnly: Prevents ordinary JavaScript running in the browser from reading the cookie. This helps reduce certain cookie theft risks.

Secure: Tells the browser to send the cookie only over secure HTTPS connections.

SameSite: Controls when cookies are sent with cross-site requests and helps reduce certain cross-site request forgery risks.

Expires or Max-Age: Controls how long the cookie remains valid.

Session Security

Applications should generate unpredictable session identifiers and protect them from unauthorized access.

Session identifiers should be regenerated after important authentication changes, such as successful login, to help prevent session fixation.

Sessions should expire according to appropriate inactivity and absolute lifetime policies. Users should also be able to log out securely.

Session Process

Tokens and JSON Web Tokens (JWT)

A token is a piece of data used by an application to represent information or authorization related to a user or system.

In web applications, authentication tokens may be issued after a successful login. The client then presents the token when requesting access to protected resources.

JSON Web Token (JWT)

JSON Web Token is a compact format for representing claims between parties. It is commonly used in web authentication and authorization systems.

A signed JWT commonly contains three parts: a header, a payload, and a signature.

Header

The header identifies the token type and the cryptographic algorithm or key information used for signing.

Payload

The payload contains claims, which are statements about a user or other information. It may include a subject identifier, issuer, expiration time, or other application-defined data.

Signature

The signature allows the receiving system to verify that the token has not been modified and was issued by a trusted party, provided the verification is correctly implemented.

Important JWT Security Considerations

A signed JWT is not automatically encrypted. Its header and payload can generally be read by anyone who obtains the token. Sensitive information should not be placed in a normal signed JWT unless it is appropriately protected.

Applications should verify the token signature, allowed algorithm, issuer, audience, and expiration time as appropriate.

Tokens should be stored and transmitted securely. They should have suitable expiration periods, and applications should plan how to handle revocation and token theft.

Encryption and HTTPS

Encryption is the process of transforming readable information into an encoded form so that it cannot be easily understood without the appropriate decryption key.

It helps protect sensitive information during storage and transmission.

Symmetric Encryption

Symmetric encryption uses the same secret key for encryption and decryption. Both parties must have access to the key and protect it from unauthorized disclosure.

Asymmetric Encryption

Asymmetric encryption uses a pair of related keys: a public key and a private key. The public key can be shared, while the private key must remain protected.

HTTPS

Hypertext Transfer Protocol Secure (HTTPS) protects communication between a browser and a web server using Transport Layer Security (TLS).

HTTPS helps protect information against eavesdropping and unauthorized modification while it travels between the browser and server. It also helps authenticate the server through its digital certificate.

HTTP vs HTTPS

HTTP: Transfers web information without the transport encryption and authentication provided by HTTPS.

HTTPS: Uses TLS to protect communication and authenticate the server.

Importance of HTTPS

Protects login credentials during transmission.

Helps protect personal and financial information.

Reduces the risk of network-based data interception.

Helps users verify that they are communicating with the intended website.

HTTPS does not automatically make a website secure against every attack. The application must still protect its accounts, databases, server configuration, and user input.

Common Web Security Threats

Web applications may contain security vulnerabilities that attackers can exploit to steal information, gain unauthorized access, modify data, or interrupt services.

Understanding common threats helps developers recognize risks and apply appropriate protective measures.

Common Web Application Attacks

SQL Injection: An attack that manipulates database queries through unsafe handling of user input.

Cross-Site Scripting (XSS): An attack that causes malicious scripts to execute in another user's browser.

Cross-Site Request Forgery (CSRF): An attack that tricks an authenticated browser into submitting an unwanted request to a website.

Brute-Force Attack: An attempt to guess passwords or other credentials by repeatedly trying possible combinations.

Phishing: A deceptive technique that tricks users into revealing credentials or sensitive information.

Session Hijacking: An attack that involves obtaining or misusing another user's active session.

Denial-of-Service (DoS): An attack that attempts to make a service unavailable by overwhelming or disrupting it.

SQL Injection

SQL Injection is a security vulnerability that occurs when an application places untrusted user input directly into a database query without proper separation between data and SQL instructions.

Attackers may exploit this weakness to bypass login checks, retrieve unauthorized records, modify database information, or delete data.

How SQL Injection Happens

Consider a login application that builds an SQL query by combining a username and password directly with a SQL statement. 

SELECT *
FROM users
WHERE username = 'USER_INPUT'
AND password = 'PASSWORD_INPUT';

If the application inserts untrusted values directly into the query, specially crafted input may change the meaning of the SQL statement.

The problem is not the use of a login form itself. The problem is constructing database commands unsafely using untrusted input.

How to Prevent SQL Injection

Parameterized Queries: Use prepared statements with parameters instead of combining user input directly into SQL commands.

Input Validation: Validate user input according to the expected format, length, and allowed values.

Least Privilege: Give database accounts only the permissions required by the application.

Safe Error Handling: Avoid displaying database details, table names, or internal queries to ordinary users.

Safe Parameterized Query Example

// Example using a parameterized SQL query

const query = `
    SELECT id, username
    FROM users
    WHERE username = ?
`;

db.execute(query, [username]);

The placeholder keeps the user-provided value separate from the SQL statement. The exact syntax depends on the database library being used.

Cross-Site Scripting (XSS)

Cross-Site Scripting is a web security vulnerability that allows an attacker to inject malicious scripts into a webpage viewed by other users.

If the application handles and displays untrusted content unsafely, a browser may execute the injected script in the context of the affected website.

Types of XSS

Stored XSS: Malicious script content is saved by the application, such as in a database, and later displayed to other users.

Reflected XSS: Malicious content is included in a request and immediately reflected in the application's response without proper handling.

DOM-Based XSS: A vulnerability caused by unsafe client-side JavaScript handling of untrusted data in the Document Object Model.

Possible Effects of XSS

Attackers may manipulate webpage content, perform actions as the affected user, or access information available to scripts in the compromised page.

The actual impact depends on the application's security controls, browser protections, and the privileges available to the script.

How to Prevent XSS

Escape or encode untrusted data according to the context in which it is displayed.

Avoid inserting untrusted content using unsafe DOM operations such as innerHTML.

Use safe text-handling methods such as textContent when displaying ordinary text.

Apply a properly configured Content Security Policy (CSP) as an additional protective layer.

Validate input where appropriate, but do not rely on input validation alone to prevent XSS.

Safer JavaScript Example

const userInput = "User-provided message";

const output = document.getElementById("message");

output.textContent = userInput;

The textContent property treats the supplied value as text instead of interpreting it as HTML markup.

Cross-Site Request Forgery (CSRF)

Cross-Site Request Forgery is an attack that tricks a user's browser into sending an unwanted request to a website where the user is already authenticated.

This can happen when a website relies only on automatically submitted browser credentials, such as session cookies, without verifying that the request was intentionally initiated by the user.

Example Scenario

A user logs in to an online banking website and receives an authenticated session cookie. The user then visits a malicious website while still logged in.

If the banking application does not properly protect sensitive actions, the malicious website may attempt to cause the browser to send an unwanted request.

How to Prevent CSRF

CSRF Tokens: Use unpredictable tokens that the application verifies when processing state-changing requests.

SameSite Cookies: Configure cookies with an appropriate SameSite policy to limit certain cross-site cookie requests.

Origin Checking: Validate request origins or referer information where appropriate.

Safe HTTP Methods: Do not use GET requests for operations that change important application data.

CSRF protection is particularly important for applications that use browser-managed cookies for authentication.

Brute-Force Attacks

A brute-force attack is an attempt to gain unauthorized access by repeatedly guessing passwords, PINs, or other credentials.

Attackers may try many possible combinations until they find a matching credential.

Common Forms of Password Attacks

Simple Brute Force: Attempts many possible password combinations.

Dictionary Attack: Uses a list of common passwords and words to guess credentials.

Credential Stuffing: Uses previously exposed username and password combinations from other services to attempt logins.

How to Prevent Brute-Force Attacks

Apply rate limiting to restrict repeated login attempts.

Use MFA or phishing-resistant authentication methods where possible.

Monitor unusual login patterns and suspicious activity.

Use appropriate temporary delays or risk-based additional verification.

Avoid permanent account lockouts that attackers could abuse to deny service to legitimate users.

Other Web Security Threats

Phishing

Phishing is a social engineering technique in which attackers impersonate trusted individuals or organizations to trick users into revealing sensitive information.

Users may receive fake emails, messages, or links that lead to fraudulent login pages.

Protection includes checking website addresses, avoiding suspicious links, using MFA, and providing security awareness training.

Session Hijacking

Session hijacking occurs when an attacker obtains or misuses another user's active session identifier or authentication token.

Secure HTTPS communication, protected cookies, session expiration, and session rotation help reduce session-related risks.

Denial-of-Service (DoS)

A Denial-of-Service attack attempts to make a website or service unavailable by overwhelming or disrupting its resources.

A Distributed Denial-of-Service (DDoS) attack uses multiple systems or devices to generate attack traffic.

Protection may include traffic filtering, rate limiting, network monitoring, and specialized DDoS mitigation services.

Security Misconfiguration

Security misconfiguration occurs when a system is deployed with unsafe or incorrect settings.

Examples include default passwords, unnecessary enabled services, exposed error messages, excessive permissions, and publicly accessible sensitive files.

Broken Access Control

Broken access control occurs when an application does not properly enforce permission rules. A user may be able to view or modify resources that should be restricted.

Developers should verify permissions on the server for every protected resource and action. Hiding a button in the interface is not sufficient security.

Web Security Best Practices

Developers should follow security practices throughout the design, development, deployment, and maintenance of a web application.

Secure Authentication

Use secure password hashing, MFA, protected password reset procedures, and rate limiting for login attempts.

Proper Authorization

Check permissions on the server before allowing users to access sensitive information or perform protected actions.

Input Validation

Validate user input according to the expected data type, length, and format. Treat all external input as untrusted.

Output Encoding

Encode untrusted content before displaying it in a webpage. This helps prevent malicious input from being interpreted as executable HTML or JavaScript.

Use HTTPS

Protect communication between users and web servers using HTTPS and properly configured TLS.

Secure Cookies and Sessions

Use secure cookie attributes, unpredictable session identifiers, appropriate expiration policies, and safe logout procedures.

Database Security

Use parameterized queries, restrict database permissions, protect database credentials, and maintain secure backups.

Software Updates

Keep web frameworks, libraries, servers, plugins, and operating systems updated to address known security vulnerabilities.

Error Handling

Display understandable error messages to users without revealing internal system details, database information, file paths, or sensitive configuration.

Logging and Monitoring

Record important security events, such as failed logins, permission changes, and suspicious activities. Logs should be protected and should not unnecessarily contain passwords, tokens, or other sensitive information.

Regular Backups

Maintain secure backups and test the restoration process. Backups help organizations recover from data loss, hardware failure, and certain security incidents.

Security Headers

HTTP security headers can provide additional browser protections. Examples include Content-Security-Policy, Strict-Transport-Security, X-Content-Type-Options, and frame-related protections.

Practical Example: Secure Login System

A login system allows registered users to access protected areas of a website. It usually contains an identification field, password field, and login button.

HTML Login Form

<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">

    <title>Login Form</title>

    <style>
        body {
            font-family: Arial, sans-serif;
            background: #f1f0f5;
            color: #202641;
            display: flex;
            justify-content: center;
            align-items: center;
            min-height: 100vh;
            margin: 0;
        }

        .login-container {
            background: white;
            width: 90%;
            max-width: 380px;
            padding: 30px;
            border-radius: 10px;
            box-sizing: border-box;
        }

        h1 {
            text-align: center;
            color: #174ea6;
        }

        label {
            display: block;
            margin: 15px 0 6px;
        }

        input {
            width: 100%;
            padding: 12px;
            box-sizing: border-box;
            border: 1px solid #aaa;
            border-radius: 5px;
        }

        input:focus {
            outline: 3px solid #347fe0;
            outline-offset: 2px;
        }

        button {
            width: 100%;
            margin-top: 20px;
            padding: 12px;
            background: #174ea6;
            color: white;
            border: none;
            border-radius: 5px;
            cursor: pointer;
        }

        button:focus {
            outline: 3px solid #202641;
            outline-offset: 3px;
        }

        .message {
            margin-top: 15px;
            text-align: center;
        }
    </style>
</head>

<body>

    <main class="login-container">

        <h1>User Login</h1>

        <form action="/login" method="post">

            <label for="email">
                Email Address
            </label>

            <input
                type="email"
                id="email"
                name="email"
                autocomplete="username"
                required>

            <label for="password">
                Password
            </label>

            <input
                type="password"
                id="password"
                name="password"
                autocomplete="current-password"
                required>

            <button type="submit">
                Login
            </button>

        </form>

        <p class="message">
            Enter your account credentials to continue.
        </p>

    </main>

</body>
</html>

This example provides the front-end structure of a login form. The form sends its information to a server-side login endpoint using the POST method.

The HTML form alone does not authenticate users or protect passwords. A real application must implement secure server-side credential verification, password hashing, session management, authorization, and other security controls.

Login System Process

The user enters an email address and password.

The browser submits the credentials through a secure connection.

The server validates the submitted information and checks the password against the stored password hash.

If the credentials are valid, the server establishes an authenticated session or issues an appropriate authentication token.

The server checks the user's permissions before allowing access to protected pages.

Web Security Testing

Web security testing is the process of identifying vulnerabilities and evaluating whether a website or application protects its data and resources properly.

Vulnerability Scanning

Vulnerability scanning uses automated tools to identify known weaknesses, outdated software, and common security configuration problems.

Penetration Testing

Penetration testing is an authorized security assessment in which testers attempt to identify and safely demonstrate exploitable weaknesses within an agreed scope.

Authentication Testing

Authentication testing checks whether login procedures, password resets, MFA, and session handling work securely.

Authorization Testing

Authorization testing checks whether users can access only the resources and actions permitted by their roles and permissions.

Input Validation Testing

This testing checks how the application handles invalid, unexpected, and potentially malicious input.

Common Security Testing Tools

OWASP ZAP: An open-source web application security testing tool that can help identify common vulnerabilities.

Burp Suite: A web security testing platform used to inspect and test HTTP requests and application behavior.

Nmap: A network discovery and security auditing tool used to identify hosts and services.

OWASP Web Security Testing Guide: A guide containing methods and recommendations for testing web application security.

Security Testing Checklist

Login credentials are transmitted through HTTPS.

Passwords are stored using secure password hashing.

Authentication includes suitable protection against automated attacks.

Users cannot access another user's private records without permission.

Database queries use parameterized statements.

Untrusted content is handled safely to prevent XSS.

State-changing requests have appropriate CSRF protection where required.

Sessions and authentication tokens are protected.

Security errors do not expose sensitive information.

Software and dependencies are regularly updated.

Practical Applications of Authentication, Authorization, and Web Security

Authentication, authorization, and web security are used in different types of websites and applications to protect accounts, information, and digital services.

Educational Systems

Student portals authenticate students and teachers before allowing access. Authorization controls whether a user can view grades, manage class records, or modify academic information.

Online Banking

Banking applications use authentication to verify customers and authorization to control account access and financial transactions. Encryption and transaction monitoring help protect financial data.

E-Commerce Websites

Online stores authenticate customer accounts and protect shopping history, payment-related information, and order records.

Social Media Platforms

Social media websites use authentication to protect user accounts and authorization to manage profiles, posts, messages, and privacy settings.

Healthcare Applications

Healthcare systems use access controls to restrict medical records to authorized users and protect sensitive patient information.

Business Management Systems

Business applications use role-based permissions to separate the functions of employees, managers, accountants, and administrators.

Key Takeaways

Authentication verifies the identity of a user, device, or system.

Authorization determines what an authenticated user is permitted to access or perform.

Web security protects websites, applications, servers, databases, and user information from security threats.

The CIA Triad consists of Confidentiality, Integrity, and Availability.

Authentication methods include passwords, OTPs, biometrics, passkeys, and security keys.

Multi-Factor Authentication adds extra verification requirements to protect user accounts.

Access control models include RBAC, DAC, MAC, and ABAC.

Sessions, cookies, and tokens help maintain authenticated access between requests.

HTTPS uses TLS to protect communication between browsers and web servers.

Common web security threats include SQL Injection, XSS, CSRF, brute-force attacks, phishing, and session hijacking.

Secure development practices include input validation, output encoding, parameterized queries, secure session management, and regular software updates.

Security testing helps identify vulnerabilities and verify that protection mechanisms work correctly.
