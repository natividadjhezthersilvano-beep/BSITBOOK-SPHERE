Overview

A computer system performs different tasks through programs and processes. Programs contain instructions that tell the computer what to do, while processes represent programs that are currently being executed.

The operating system manages processes by allocating CPU time, controlling memory usage, tracking execution states, and managing system resources. This allows multiple applications and tasks to operate within the same computer system.

Learning Objectives

After completing this lesson, students should be able to:

  • Explain the concept of programs and processes.
  • Differentiate a program from a process.
  • Describe the different process states and their transitions.
  • Explain the purpose of the Process Control Block (PCB).
  • Understand process context and context switching.
  • Identify the memory components of a process.
  • Explain storage classes and linkage classes.
  • Describe process creation and termination.
  • Understand zombie and orphan processes.
  • Explain how wait() and waitpid() manage child processes.

Programs and Processes

Program

A program is a collection of instructions and functions designed to accomplish a specific task. It contains the commands that tell the computer how to perform an operation.

A program is considered a passive entity because it is stored as a file on a storage device. It does not perform any activity until it is loaded and executed.

Examples include:

  • Web browsers
  • Word processors
  • Calculator applications
  • Media players
  • Computer games

Process

A process is a program in execution. It is an active entity because it is currently performing instructions and using computer resources.

When a user opens an application, the operating system creates and manages a process. The process contains execution information, memory, and other resources needed while the application runs.

Program vs. Process

Program

  • Set of instructions or functions.
  • Passive entity.
  • Stored as a file on a storage device.
  • Does not have an active execution state.
  • Can exist without running.

Process

  • A program in execution.
  • Active entity.
  • Managed by the operating system.
  • Has different execution states.
  • Exists while being executed.

Multiple Processes from One Program

A single program can be executed multiple times. Each execution can create a separate process with its own process identifier, memory information, and execution state.

For example, opening multiple instances of a text editor can result in multiple processes running the same program.

Viewing Processes in Linux

Linux provides the top utility to display currently running processes and their resource usage. 

top

Common process information includes:

  • PID: The unique process identification number.
  • USER: The user who started the process.
  • PR: The process priority.
  • VIRT: The total virtual memory used by the process.
  • RES: The resident physical memory used by the process.
  • SHR: The shared memory size.
  • %CPU: The percentage of CPU utilization.
  • %MEM: The percentage of physical memory utilization.

Process States

A process changes its state as it executes. The operating system tracks these states to determine what a process is currently doing and whether it can use the CPU.

New

The process is being created. The operating system prepares the required information and resources before allowing it to execute.

Ready

The process is prepared to execute and is waiting for the CPU. It has the resources needed to run but has not yet been assigned processor time.

Running

The process is currently executing instructions using the CPU. A processor core executes instructions for a running process.

Waiting

The process cannot continue until a particular event occurs. For example, it may be waiting for an input operation, disk access, or another system event to finish.

Terminated or Halted

The process has completed its execution or has been stopped. The operating system handles the release of its resources.

Process State Transitions

A process moves between states depending on CPU availability, completed operations, and events handled by the operating system.

  • New to Ready: The process has been created and is ready to execute.
  • Ready to Running: The CPU scheduler selects the process for execution.
  • Running to Ready: The process loses the CPU, such as when its time slice expires.
  • Running to Waiting: The process requests an operation or waits for an event.
  • Waiting to Ready: The required event or operation is completed.
  • Running to Terminated: The process finishes or exits.

Process Control Block (PCB)

A Process Control Block is a data structure maintained by the operating system to store important information about a process. The operating system uses the PCB to manage, monitor, and control process execution.

Every process has its own process information. The PCB allows the operating system to save the current execution information and restore it when the process is scheduled again.

Information Stored in a PCB

Process State

Identifies the current state of the process, such as new, ready, running, waiting, or terminated.

Process ID

A unique identification number assigned to a process. It allows the operating system to identify and manage individual processes.

Program Counter

Stores the memory address of the next instruction that the process should execute when it resumes.

CPU Registers

Store temporary information used by the processor. These include general-purpose registers and special registers.

Stack Pointer

Contains the address of the top of the current stack. The stack stores information related to function calls, local variables, and return addresses.

CPU Scheduling Information

Contains information used by the operating system to schedule processes, including priority and other scheduling parameters.

Memory Management Information

Contains information about the memory assigned to the process, including references to its code, data, and stack areas.

Accounting Information

Records resource usage, such as the amount of CPU time consumed by the process.

I/O Status Information

Contains information about input and output operations, open files, and devices being used by the process.

PCB in Linux

Linux uses a process descriptor called task_struct to maintain information about tasks and processes.

Its information includes:

  • Process state and identification.
  • Parent process and process group information.
  • CPU registers and scheduling information.
  • Memory segment information.
  • Open files and working directory.
  • User and group identification.
  • CPU time and process accounting information.

Process Context

Process context refers to the current execution information of a process. It describes the information needed by the CPU and operating system to continue executing the process.

The process context includes the contents of CPU registers, the program counter, and the stack pointer. This information is important when a process temporarily stops running and later resumes.

Program Counter (PC)

The program counter contains the memory address of the next instruction to be executed. It allows the processor to continue from the correct instruction when the process resumes.

Stack Pointer (SP)

The stack pointer identifies the top of the current stack in memory. The stack contains information about active function calls, local variables, parameters, and return addresses.

General-Purpose Registers

These registers temporarily hold data and values required during instruction execution. They allow the CPU to perform operations efficiently without accessing memory for every value.

Thread of Execution

A thread of execution represents a sequence of instructions performed by the CPU. It follows a flow of control through the instructions of a program.

A process normally begins with a single thread of execution. A process may also contain multiple threads that perform different activities within the same process.

Example of Threads

Consider a web browser. One activity may handle the user interface, another may load a web page, and another may perform background tasks.

These activities can be handled by separate threads within the browser process, allowing different tasks to make progress.

Process and Thread

Process

  • An executing program.
  • Has its own process address space.
  • Has process management information.
  • Can contain multiple threads.

Thread

  • A sequence of execution within a process.
  • Threads in the same process share its address space.
  • Has its own execution state and stack.
  • Belongs to a process.

Context Switching

Context switching occurs when the CPU stops executing one process and switches to another process. The operating system saves the current process context and loads the saved context of the next process.

This allows multiple processes to share CPU time. Even when a processor core executes only one process at a time, rapid switching allows users to work with several applications.

How Context Switching Works

  • The CPU is executing a process.
  • An event causes the operating system to switch processes.
  • The current process information is saved in its PCB.
  • The operating system selects another ready process.
  • The selected process's saved context is restored.
  • The CPU continues executing the selected process.

Why Context Switching Is Important

Context switching allows the operating system to share CPU resources among multiple processes. It helps the system respond to different tasks and manage waiting processes.

Context-Switching Overhead

Context switching requires time because the operating system must save and restore execution information. During this activity, the CPU is performing management work instead of executing application instructions.

It can also affect performance because:

  • CPU time is spent saving and restoring process information.
  • Cache contents may become less useful after switching.
  • Translation Lookaside Buffer (TLB) entries may need attention.
  • Frequent switching can reduce overall efficiency.

Process in Memory

When a program executes, the operating system provides it with an address space. An address space is the range of virtual memory addresses available to a process.

The process uses different memory areas to store program instructions, variables, temporary data, and dynamically allocated information.

Text Segment

The text segment contains the executable instructions of a program. It stores the machine code that the CPU executes.

For example, the compiled instructions of a calculator application are stored in the program's code segment.

Data Segment

The data segment stores global and static variables used by the program. These variables have storage that exists beyond an individual function call.

Stack

The stack stores temporary information used during program execution. It commonly contains local variables, function parameters, return addresses, and function call information.

When a function is called, a stack frame is created. When the function finishes, its stack frame is removed.

Heap

The heap is the memory area used for dynamic memory allocation. A program can request memory while it is running and release it when it is no longer needed.

In C, functions such as malloc() and free() are used to allocate and release dynamically managed memory.

Program Counter and Registers

The program counter and CPU registers contain execution information used by the processor. They are part of the running context of a process rather than ordinary memory segments such as the heap and stack.

Example of Stack and Heap

#include <stdio.h>
#include <stdlib.h>

int main() {

    int number = 10;  // Local variable: typically on the stack

    int *ptr = malloc(sizeof(int));  // Dynamic memory: heap

    if (ptr == NULL) {
        return 1;
    }

    *ptr = 25;

    printf("Number: %d\n", number);
    printf("Dynamic value: %d\n", *ptr);

    free(ptr);

    return 0;
}

In this example, number is a local variable, while the memory requested by malloc() is dynamically allocated from the heap. The pointer variable ptr itself is a local variable.

Storage Classes

Storage classes describe the lifetime and storage behavior of variables in a program. They help determine how long a variable exists and where it can be used.

Static Storage Class

A variable with static storage duration retains its allocated storage throughout the execution of the program. Its value remains available between function calls when declared as a local static variable. 

#include <stdio.h>

void counter() {

    static int count = 0;

    count++;

    printf("Count: %d\n", count);
}

int main() {

    counter();
    counter();
    counter();

    return 0;
}

Output:

Count: 1
Count: 2
Count: 3

The variable count keeps its value between function calls because it has static storage duration.

Automatic Storage Class

Automatic variables are created when the block in which they are declared is entered and their lifetime ends when that block is exited. 

#include <stdio.h>

void display() {

    int number = 10;

    printf("%d\n", number);
}

int main() {

    display();

    return 0;
}

The local variable number has automatic storage duration. It is available inside the function while that function is executing.

Comparison of Storage Classes

Static Storage

  • Exists throughout program execution.
  • Retains its value between function calls.
  • Can be used for global and static local variables.

Automatic Storage

  • Exists during the execution of its block.
  • Its lifetime ends when its block exits.
  • Commonly used for ordinary local variables.

Linkage Classes

Linkage determines whether an identifier, such as a variable or function, can be referred to from other parts of a program or from other source files.

Internal Linkage

Internal linkage means that an identifier can only be referred to within the source file where it is declared.

In C, a file-scope variable or function declared with static has internal linkage. 

#include <stdio.h>

static int count = 0;

static void display() {

    printf("Count: %d\n", count);
}

int main() {

    display();

    return 0;
}

External Linkage

External linkage allows an identifier to be referred to from other source files. This is useful when a program is divided into multiple files.

A global variable or function normally has external linkage unless another declaration changes its linkage. 

/* file1.c */

int total = 100;
/* file2.c */

extern int total;

void display() {

    printf("%d", total);
}

The extern declaration tells the compiler that the variable is defined elsewhere.

No Linkage

An identifier with no linkage can only be referred to within its own scope. Ordinary local variables declared inside a function generally have no linkage.

Comparison of Linkage Classes

Types of Linkage

  • Internal: Accessible only within the source file.
  • External: Can be accessed from other source files through declarations.
  • No Linkage: Limited to its own scope.

Process Creation

Process creation occurs when the operating system creates a new process to execute a program or perform a task. Each process receives a process identifier called a PID.

Parent and Child Processes

In UNIX and Linux, an existing process can create another process. The original process is called the parent process, while the newly created process is called the child process.

The parent and child processes have separate process identifiers and can execute independently.

The fork() System Call

The fork() system call creates a new child process by duplicating the calling process. The child receives a separate process context and a logically separate address space.

Modern Linux systems commonly use copy-on-write memory management. This means memory pages are initially shared until one process needs to modify them.

Return Values of fork()

  • Zero: The code is executing in the child process.
  • Positive value: The code is executing in the parent process. The value is the child's PID.
  • Negative value: Process creation failed.

Example of fork()

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main() {

    pid_t pid = fork();

    if (pid == 0) {

        printf("This is the child process.\n");
        printf("Child PID: %d\n", getpid());

    } else if (pid > 0) {

        printf("This is the parent process.\n");
        printf("Child PID: %d\n", pid);

    } else {

        printf("Process creation failed.\n");
    }

    return 0;
}

After a successful fork(), both processes continue execution from the instruction immediately after the system call. Their output order is not guaranteed because the operating system schedules them independently.

When fork() May Fail

Process creation may fail when the system cannot provide the resources required for a new process.

  • EAGAIN: A process or system resource limit has been reached.
  • ENOMEM: The system cannot allocate the required memory or kernel structures.
  • ENOSYS: The system does not support the required operation.

Loading a Different Program Using exec()

The exec() family of functions replaces the current process image with a new program. It is commonly used after fork() when a child process needs to execute a different program.

Unlike fork(), which creates a new process, exec() does not create another process. It replaces the program being executed by the calling process.

Example of fork() and execlp()

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main() {

    pid_t pid = fork();

    if (pid < 0) {

        perror("fork failed");
        return 1;

    } else if (pid == 0) {

        printf("Child process is running.\n");

        execlp("ls", "ls", "-l", (char *)NULL);

        perror("exec failed");
        exit(1);

    } else {

        wait(NULL);

        printf("Parent process finished waiting.\n");
    }

    return 0;
}

The parent creates a child process using fork(). The child then executes the ls command using execlp(). The parent waits until the child finishes.

If an exec() function succeeds, it does not return to the original program. If it returns, an error occurred.

Process Termination

Process termination occurs when a process stops executing. After termination, the operating system releases the resources associated with the process and records the information needed for its parent to collect the exit status.

Voluntary Termination

Voluntary termination occurs when a process finishes its assigned task and exits normally. In C, a program can use return from main() or call exit() to terminate. 

#include <stdio.h>
#include <stdlib.h>

int main() {

    printf("Program is running.\n");

    exit(0);
}

An exit status of zero commonly indicates successful completion. A nonzero status commonly indicates an error or another result defined by the program.

Involuntary Termination

Involuntary termination occurs when a process is stopped before completing its intended task. This can happen because of an error, a signal, or an action taken by another process or the operating system.

Examples include:

  • A process is terminated by its parent.
  • A program encounters a segmentation fault.
  • A process receives a termination signal.
  • The operating system stops a process because of system conditions.

What Happens After Termination?

The operating system releases the process's resources. However, a terminated child process may temporarily remain in the process table so its parent can retrieve its exit status.

Zombie Process

A zombie process, also called a defunct process, is a process that has completed execution but still has an entry in the process table.

This happens when a child process terminates but its parent has not yet collected its exit status using a function such as wait() or waitpid().

How a Zombie Process Occurs

  • A parent process creates a child process.
  • The child process completes its execution.
  • The child calls exit() or returns from its main function.
  • The parent does not collect the child's exit status.
  • The child remains as a zombie entry in the process table.

Problems Caused by Zombie Processes

A zombie process no longer executes instructions, but its process table entry remains until it is reaped. Large numbers of zombies can consume process table entries and process IDs, eventually interfering with process creation.

How to Prevent Zombie Processes

A parent process should collect the exit status of its child processes using wait() or waitpid(). This process is called reaping.

Orphan Process

An orphan process is a process that is still executing after its original parent process has terminated.

Unlike a zombie process, an orphan process is still active. It can continue performing its assigned tasks even though its original parent no longer exists.

How an Orphan Process Occurs

  • A parent process creates a child process.
  • The parent terminates before the child.
  • The child continues executing.
  • The child becomes an orphan process.

On Linux, an orphan process is generally adopted by an appropriate reaper process, commonly the system's init process or another configured subreaper.

Zombie vs. Orphan Process

Zombie Process

  • Has already finished execution.
  • Remains in the process table.
  • Waiting for its exit status to be collected.
  • Reaped using wait() or waitpid().

Orphan Process

  • Is still executing.
  • Continues running without its original parent.
  • Can be adopted by another process.
  • Continues until it finishes or is terminated.

Managing Child Processes Using wait()

The wait() system call allows a parent process to wait for a state change in one of its child processes. It can collect information about a child that has terminated and allow the operating system to remove its zombie entry.

A parent commonly calls wait() to ensure that its child processes finish and that their exit statuses are collected.

Example of wait()

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {

    pid_t pid = fork();

    if (pid == 0) {

        printf("Child process is working.\n");

        exit(0);

    } else if (pid > 0) {

        wait(NULL);

        printf("Parent collected the child process.\n");

    } else {

        perror("fork failed");
        return 1;
    }

    return 0;
}

The parent process waits until the child terminates. After collecting the child's status, the child is reaped.

Checking the Child Exit Status

The parent can use the status value returned through wait() to determine how the child terminated. The macros from sys/wait.h help interpret the status.

  • WIFEXITED(status) checks whether the child terminated normally.
  • WEXITSTATUS(status) retrieves the child's exit status when it terminated normally.
  • WIFSIGNALED(status) checks whether the child terminated because of a signal.
  • WTERMSIG(status) identifies the signal that terminated the child.
  • WIFSTOPPED(status) checks whether the child was stopped by a signal.
  • WSTOPSIG(status) identifies the signal that stopped the child.

Managing Specific Child Processes Using waitpid()

The waitpid() system call provides more control over which child process the parent waits for. Unlike wait(), which waits for any eligible child, waitpid() can wait for a specific child process using its PID.

Difference Between wait() and waitpid()

wait()

  • Waits for an eligible child process.
  • Provides less selection control.
  • Commonly used to collect any child's status.

waitpid()

  • Can wait for a specific child process.
  • Provides process selection and additional options.
  • Useful when managing several child processes.

Example of waitpid()

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {

    pid_t pid = fork();
    int status;

    if (pid == 0) {

        printf("Child process is running.\n");

        exit(5);

    } else if (pid > 0) {

        waitpid(pid, &status, 0);

        if (WIFEXITED(status)) {

            printf("Child exited with status: %d\n",
                   WEXITSTATUS(status));
        }

    } else {

        perror("fork failed");
        return 1;
    }

    return 0;
}

The parent waits for the specific child identified by pid. When the child terminates, the parent collects its exit status.

Understanding waitpid() Parameters

waitpid(pid, &status, options);
  • pid: Specifies which child process to wait for.
  • status: Stores information about the child's state change.
  • options: Controls how the function waits. A value of 0 means normal blocking behavior.

Practical Applications of Process Management

Process management is used in everyday computing because modern operating systems need to manage multiple applications, background tasks, and system services.

Multitasking

Process management allows users to run a browser, document editor, and music player while the operating system shares CPU resources among them.

Application Execution

When a user opens an application, the operating system creates and manages a process to execute its instructions.

Background Services

Operating systems run background processes to perform tasks such as checking updates, managing network connections, and monitoring system activity.

Resource Management

The operating system monitors CPU usage, memory allocation, and other resources to prevent processes from interfering unnecessarily with one another.

System Monitoring

Tools such as Linux top and ps allow administrators to view running processes and examine their resource consumption.

Key Takeaways

  • A program is a set of instructions, while a process is a program in execution.
  • The operating system manages processes and their resources.
  • Process states describe the current execution condition of a process.
  • The Process Control Block stores important process information.
  • Process context contains the information needed to resume execution.
  • Context switching allows the CPU to switch between processes.
  • A process address space includes code, data, stack, and heap areas.
  • Storage classes determine the lifetime of variables.
  • Linkage classes determine how identifiers can be accessed across source files.
  • The fork() system call creates a child process in UNIX and Linux.
  • The exec() family replaces the current process image with another program.
  • A zombie process has terminated but has not yet been reaped.
  • An orphan process continues executing after its original parent terminates.
  • wait() and waitpid() allow parent processes to collect child process status.
